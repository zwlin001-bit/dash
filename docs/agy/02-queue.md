### 3 · T0.2 可移植 SQL 访问层

| | |
|---|---|

### 4 · T0.3 迁移框架 + 初始 DDL

| | |
|---|---|
| 前置 | T0.2 |
| 分支 | `agy/T04-migrations` |
| 迁移编号 | **0001（本任务独占）** |
| 权威定义 | `M0-foundation.md` 的 `T0.3` |
| 设计依据 | `02-database.md` 全文、`06-speedtest.md` §2 |

**这是关键路径上最长、最容易写歪的一个任务。**

**易错点（Oracle 侧，逐条对照 `02-database.md` §1.2）**
- **Oracle 没有 `BIGINT`**，用 `NUMBER(19)`
- **Oracle 没有 `BOOLEAN`**，用 `NUMBER(1)` 存 0/1
- **不要用 `TIMESTAMP`/`DATE` 列**，时间一律 `NUMBER(19)` 存 epoch 毫秒
- **不要用 `DOUBLE PRECISION`**，用 `BINARY_DOUBLE`（前者在 Oracle 会退化成软件浮点，聚合慢一个数量级）
- 主键用 `VARCHAR2(26)` 存 ULID，**不要用 `CHAR`**（空格补齐比较语义会坑人）
- 字符串用 `VARCHAR2(n CHAR)`，**`CHAR` 语义**，否则中文按字节算会截断
- 标识符全小写、不加引号、≤30 字符、避开 §1.3 的保留字黑名单
- 两份 DDL（`.oracle.sql` / `.mysql.sql`）**表和列必须完全对应**，要写对比测试

**必须包含的种子数据**：`speedtest_targets` 的电信/联通/移动三组内置目标，`is_builtin=1`。
**具体 IP / URL 只能在迁移里，不许硬编码进 Go 代码。**

**边界**：只建表和迁移框架，**不写任何读写这些表的业务代码**。

**完成判据**：空库上 `make migrate` 建出全部表；重复执行幂等；Oracle 与 MySQL 表结构对比测试通过。

### 9 · T1.1 采集层

| | |
|---|---|
| 前置 | T0.1 |
| 分支 | `agy/T09-collect` |
| 迁移编号 | 无 |
| 权威定义 | `M1-agent.md` 的 `T1.1` |
| 设计依据 | `03-agent.md` §3、`adr/0003-*.md` |

**易错点**
- **不许引入 gopsutil 或任何 psutil 类库。** 这条是硬红线，验收会 `go list -m all` 检查
- CPU 用 `/proc/stat` 两次采样求差，**`steal` 计入 busy**（VPS 上被宿主抢走的时间用户能感觉到）
- **不 sleep、不阻塞**采样
- 每个 `/proc` 文件用**复用的固定缓冲**一次读完，不用 `bufio.Scanner`（它每行都分配）
- 采集失败的项**留空不填 0**
- Alpine 的 `/proc/meminfo` 可能缺字段，缺 `MemAvailable` 要回退，**不许 panic**

**必须做成注册表形状**：加一个采集项 = 加一个文件 + 一行 `Register()`，**不改主循环**。
验收时会让你现场演示这一点。

**完成判据**：基准测试里 fast 采集一轮的 `allocs/op` 是个位数。

### 10 · T1.3 传输层

| | |
|---|---|
| 前置 | T0.5 |
| 分支 | `agy/T10-transport` |
| 迁移编号 | 无 |
| 权威定义 | `M1-agent.md` 的 `T1.3` |
| 设计依据 | `04-protocol.md` §1、§5 |

**易错点**
- token 放 `Authorization: Bearer`，**不放 query string**（会进反代访问日志）
- 重连退避必须**带 ±20% 抖动**，否则所有 agent 会同时重连打垮服务端

  验收时会故意下发一个未知方法

**完成判据**：断网 2 分钟再恢复，自动重连且内存无增长。

### 12 · T2.2 批量落库 ▶ 里程碑 A

| | |
|---|---|
| 前置 | T2.1、T1.2 |
| 分支 | `agy/T12-ingest` |
| 迁移编号 | 无 |
| 权威定义 | `M2-server-ingest.md` 的 `T2.2` |
| 设计依据 | `02-database.md` §5.4、§5.7 |

**这个任务合并后，端到端链路就通了：真机装 agent → 数据进 ADB。**

**易错点**
- **绝不一条上报一次 INSERT。** ADB 在网络另一端，往返延迟是主要成本。5 秒批量 flush
- flush 失败重试 3 次后**丢弃最老一批并计数告警**，
  **不许阻塞采集链路**——监控数据不值得为了不丢而把链路堵死
- 前端实时视图读**内存最新值缓存**，不查库。数据库短暂不可用时实时视图仍要正常
- 计数器 reset：`delta = cur >= prev ? cur - prev : cur`。
  `prev` 存内存，进程重启时从数据库最近一行恢复。
  **这条不做，机器一重启流量统计就会出现天文数字**

**完成判据**：30 个模拟 agent 上报 10 分钟行数正确；断库 30 秒恢复后写入继续且实时视图全程可用；模拟重启后 `traffic_up` 无负值无异常巨值。

### 13 · T2.3 Rollup 与保留期

| | |
|---|---|
| 前置 | T0.3 |
| 分支 | `agy/T13-rollup` |
| 迁移编号 | 无 |
| 权威定义 | `M2-server-ingest.md` 的 `T2.3` |
| 设计依据 | `02-database.md` §5.5、§5.6 |

**易错点**
- rollup 用**可移植 SQL 在数据库内完成**，`INSERT ... SELECT ... GROUP BY FLOOR(ts_ms/60000)`。
  **不要把数据拉到应用层再算**
- **只处理已关闭的时间桶**，否则半个桶会被写两次
- 幂等靠「先按 bucket 区间 DELETE 再 INSERT，一个事务」，不用 upsert
- `_1h` 从 `_1m` 聚合、`_1d` 从 `_1h` 聚合，**不回读 raw**
- **逐级聚合的 avg 必须加权**：`SUM(x_avg * sample_cnt) / SUM(sample_cnt)`。
  直接 `AVG(x_avg)` 是错的，这个 bug 很难被发现
- 清理按**时间区间**分块 DELETE（每次一小时），**不用 `LIMIT`**，每轮之间 sleep

**完成判据**：抽查 `_1m` 的 avg/max/min 与 raw 直接算的结果一致；重复跑 rollup 结果不变。

### 21 · T4.2 Agent 探测模块

| | |
|---|---|
| 前置 | T1.2 |
| 分支 | `agy/T21-speedtest-probe` |
| 迁移编号 | 无 |
| 权威定义 | `M4-speedtest.md` 的 `T4.2` |
| 设计依据 | `06-speedtest.md` §3 |

**这个任务最容易击穿 T1.2 的资源预算，九条约束逐条对照。**

**易错点**
- **只在收到指令时执行**，绝不进 fast/slow 采集循环
- **同一时刻最多一个探测**，排队不并发
- `http_down` 受 `max_bytes` 和 `max_duration_s` **双重限制，先到先停**
- 下载数据读进**复用的固定缓冲后直接丢弃**，不落盘不进堆
- 探测结束调 `debug.FreeOSMemory()` 把堆还给系统
- **`tcping` 用 TCP 握手耗时，不用 ICMP**——agent 非 root 跑，发不了 raw socket。
  这条不提前知道必然踩
- `http_up` 失败**不算任务失败**（多数公开测速点不支持上行）
- 下行速率要**去掉前 1 秒的 TCP 慢启动窗口**再算，否则数字会偏低很多

**完成判据**：跑 50MB 下行，RSS 峰值 ≤40MB 且结束后 60 秒内回落到 20MB 内；全程上报不中断；同时下发 3 个探测确认是串行的。

### 24 · T5.2 setup.sh

| | |
|---|---|
| 前置 | T0.3、T0.4、T5.0 |
| 分支 | `agy/T24-setup` |
| 迁移编号 | 无 |
| 权威定义 | `M5-deploy.md` 的 `T5.2` |
| 设计依据 | `05-deployment.md` 全文 |

**用户视角只有一句话：`sudo ./setup.sh install`，只问域名。**

**易错点**
- **POSIX sh**，Alpine busybox ash 能跑
- **交互只有一个必填项：域名。** 其余全有默认值
- 默认 443，`setcap cap_net_bind_service=+ep` 后**以非 root 用户运行**
  （Alpine 要先 `apk add libcap`）。验收会查 `ps -o user=`
- **域名写 `settings.site.domain`，不写配置文件**
- ADB 是 mTLS，`--wallet` 是**必填**，wallet 装到 `/etc/dash/wallet/`（0700）
- `status` 要检查 **wallet 剩余有效期**——证书过期会导致连不上库，这种故障最难查
- `upgrade` 健康检查失败**自动回滚旧二进制**
- `uninstall` **数据库永远不动**

**完成判据**：三个系统各跑一次 install 都能用域名访问；重复执行不报错；`ps -o user=` 不是 root。
