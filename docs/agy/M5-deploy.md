只依赖工程骨架，不依赖任何后端接口，因此可以在 Wave 1 就开工。

统一的 API 客户端封装、**监控与测速共用的时序图表组件**（先接 mock 数据）。

**约束**

- 图表组件的入参形状按 `02-database.md` §6 的查询返回定义好，后端接上时不改组件

**验收**：`make build` 后 `bin/dashd` 单文件启动就能打开登录页；图表组件用 mock 数据能渲染四个跨度。

## T5.2 setup.sh

**用户视角只有一句话：`sudo ./setup.sh install`，只问域名。**

**交付物**：`setup.sh`，子命令 `install` / `upgrade` / `uninstall` / `status`。

**约束**
- **POSIX sh**，Alpine 的 busybox ash 能跑
- **交互只有一个必填项：域名。** 其余全部有默认值
- 非交互形式：`./setup.sh install --domain x --yes`
- 全部子命令**幂等**，可重复执行
- 默认监听 **443**；`setcap cap_net_bind_service=+ep` 后**以非 root 用户 `dashd` 运行**
  （Alpine 需要先 `apk add libcap`）
- 证书用 `autocert`，缓存在 `/var/lib/dash/certs`；80 端口只做 ACME 挑战 + 301 跳转
- **域名写入 `settings.site.domain`，不写配置文件**
- 安装完成打印：访问地址、初始管理员密码（只显示一次）、
  **需要备份的两个文件 `/etc/dash/master.key` 和 `/etc/dash/config.toml`**
- `upgrade` 健康检查失败**自动回滚到旧二进制**
- `uninstall` 默认保留 `/etc/dash` 和数据库，`--purge` 才删配置，**数据库永远不动**

**验收**
- Debian / Ubuntu / Alpine 三个干净环境各跑一次 `install`，装完能用域名访问
- 重复 `install` 不报错
- `status` 正确显示服务状态、版本、数据库连通性、证书到期时间、在线 agent 数
- `ps -o user= -p $(pidof dashd)` 输出不是 root

## T5.3 域名在线修改

**交付物**：设置页改域名 → 校验解析 → 写库 → 重新签发证书 → 切换。

**约束**
- 改域名**不重启进程**
- 新证书签发失败**自动回滚到旧域名**并提示原因
- 校验新域名的 A/AAAA 记录确实指向本机再动手，避免把自己锁在外面

**验收**：改成一个未解析的域名被拒绝并给出原因；改成正确解析的域名后，
新域名可访问、旧域名停止服务、进程未重启。
