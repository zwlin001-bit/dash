## 约束

- ★ **多对多**：一个事件类型可配多个渠道（同时发两个 TG 号），
  一个渠道可接多个类型。这是需求核心，别做成一对一
- `event_pattern` **只支持末尾 `*` 通配**（`node.*`、`*`），
  **不做正则**——正则会让人写出自己都看不懂的规则
- `min_severity`：低于该级别不发
- `throttle_s`：同一 `(rule, target_id)` 在窗口内只发一条。
  **节点反复上下线时靠它救命**
- `quiet_start_min` / `quiet_end_min` 免打扰：
  时段内的通知**攒着不丢**，出时段合并成一条发出
- 时区偏移从 `settings` 读，**不用服务器本地时区**
- 一个事件匹配多条规则时，**每条规则各自独立发一次**（不去重），
  但同一规则的 throttle 独立计算

## 验收

1. 配置「`node.offline` → TG-A + TG-B」，一次离线事件产生两条待投递记录
2. 配置「`node.*` → TG-A」，`node.online` 和 `node.offline` 都能匹配上
3. `min_severity=warning` 时，info 级事件不产生投递
4. `throttle_s=300`，5 分钟内同一节点连续 10 次离线事件只产生 1 条投递
5. 免打扰时段内的事件被标 `quiet_held`，出时段后合并发出且**一条不丢**
6. 规则停用后立即不再匹配

## 边界

只决定「该发给谁」，**不负责渲染和发送**。产出待投递意图即可。
