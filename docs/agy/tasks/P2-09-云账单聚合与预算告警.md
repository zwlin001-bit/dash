## 约束

### 表与字段

照 `15-cloud-billing.md` §2。两处容易做错的：

- ★ **`period` 用 `"2026-09"` 字符串**，不是时间戳。跨时区没歧义、可比可排序
- ★ **`cloud_resource_id` 必须可空。** 账单里大量条目不对应任何实例
  （公网带宽包、快照、OSS）。**不要为了外键完整性把它们丢掉** ——
  那正是「钱花哪儿了」最容易失控的部分

### 币种：原币存储，禁止自动折算

★ 跨账号汇总时**同币种相加，不同币种分组显示**，不许偷偷折算成人民币。
汇率会变，折算过的历史数字既不可复现也不可对账。
界面上并排列「CNY 1234.56 / USD 78.90」即可。

### 同步

- 走 Job 引擎（P2-03），job kind = `bill.sync`
- ★ **当月账单是变动的**，每次同步覆盖当月；
  **已关账的历史月份只拉一次**（`sync_state='ok'` 且 `period` < 当月即跳过）
- 默认回补最近 12 个月，可配
- ★ **账单 API 的限流比 ECS 严得多。** 回补 12 个月要**串行 + 退避**，
  不许并发轰。某个账号失败写 `error_text`，**不阻塞其他账号**

阿里云用 `QueryBillOverview`（月度总览）+ `QueryInstanceBill`（明细，**要分页**），
endpoint 沿用 `cloud_accounts.account_site`。

### 预算告警：复用告警引擎，不新造

★ **不要写第二套告警状态机。** 给 P2-08 的 `alert_rules` 加一个 `rule_kind = 'budget'`：

| rule_kind | threshold 含义 | 数据来源 |
|---|---|---|
| `budget` | 当月用量 ÷ 预算 的比例（0.8 = 80%） | `bill_periods.total_amount` ÷ `bill_budgets.amount` |

每小时评估一次，去抖 / 静默 / 恢复通知全部沿用既有状态机。

事件类型按 `09-events-notify.md` §2.1 登记：

| event_type | 默认级别 | 默认处置 |
|---|---|---|
| `billing.budget_warning` | warning | store+notify |
| `billing.budget_exceeded` | critical | store+notify |
| `billing.sync_failed` | error | store+notify |

### 界面

- 顶部：当月合计（**按币种分组**）、环比上月、预算进度条

- 明细：按资源类型 / 单资源 / 标签三种维度切换汇总

## 验收

1. 配一个真实阿里云账号 → 同步 → **当月合计与阿里云控制台「费用中心」对得上**
2. 回补 12 个月 → 历史月份数据落库；★ **再同步一次，已关账月份不重复拉**
   （日志或 `synced_at_ms` 能证明）
3. ★ 账单里的公网带宽包 / 快照等条目 → **落进 `bill_items` 且 `cloud_resource_id` 为空**，
   界面上在「未关联资源」组里能看到，没被丢弃
4. 两个不同币种的账号 → 合计处**分组显示**，没有被折算成同一种币
5. 预算设 100 元、当月已用 85 元 → 收到 `billing.budget_warning`；
   超过 100 → 收到 `billing.budget_exceeded`
6. ★ 连续几小时都超预算 → **按 `silence_s` 去重**，不是每小时推一次
7. 把 BSS 权限去掉 → `billing.sync_failed` 推出来，`error_text` 里**无 AK/SK 明文**，
   且**其他账号的同步不受影响**
8. 按标签汇总：给两台机器打 `proxy` 标签 → 汇总金额 = 这两台的账单之和
9. `make lint`（含 SQL 方言与 CSS token）、`make test` 全绿
10. `01-architecture.md` §3.3 的方法表里有 `bill.list`
