# P2-14 站点域名可维护 + 装机命令用对域名

> 第二期 · 任务 14 ｜ 前置：无 ｜ 分支：`agy/p2-14-site-domain` ｜ **预计半天**

> ★ **完成后必须自己 `git push -u origin <分支名>`**。

## 问题

一键装机命令生成出来是：

```
curl -fsSL https://custom.domain.org/install.sh | sh -s -- --enroll <token>
```

域名不对。代码本身是对的 —— `internal/inventory/enroll.go:117` 读的是
`settings.site.domain`。问题在于**这个值一旦错了，界面上改不了**：

```go
// internal/settings/settings.go:135
// 不允许修改 site.domain 与 site.console_domain（第一期只读展示）
```

第一期这么定是因为改域名要重签证书。但现在的后果是：
**装机命令一直发错域名，用户只能去改数据库。**

## 目标

**让站点域名在界面上可维护，并且改完能看出证书要不要重签。**

## 约束

### 放开编辑，但要有护栏

- `site.domain`（agent 接入）与 `site.console_domain`（控制台）改为可编辑
- ★ **保存前做格式校验**：合法域名或 `域名:端口`，不许带 scheme、不许带路径
- ★ **保存后立刻在页面上回显新的装机命令**，让用户当场确认对不对 ——
  这是最直接的验证方式
- 改动写 `audit_log`

### 证书提示

改了 `site.domain` 之后，现有证书的 CN/SAN 就对不上了。

- ★ **保存后显示醒目提示**：「域名已更新。现有证书仍是旧域名签发的，
  请在服务器上执行 `sudo ./setup.sh install --agent-domain <新域名>` 重新签发」
- ★ **不要在界面上自动触发重签** —— 那要 root 权限、要动 nginx，
  失败了用户会连控制台都进不去。第二期先给提示

### 装机命令

- `enroll.go` 的 fallback `localhost:8080` 保留，但★ **当用的是 fallback 时，
  界面上要标红提示「站点域名未配置，此命令无法在其他机器上执行」**，
  不要默默给一条用不了的命令

## 验收

1. 设置页能改 `site.domain`，保存后**装机命令当场变成新域名**
2. 填 `https://x.com` 或 `x.com/path` → **被拒绝**并说明原因
3. 改完显示重签证书的提示，且提示里的命令可以直接复制执行
4. 把 `site.domain` 清空 → 装机命令区域**显示红色警告**，不是默默给 localhost
5. 改动进 `audit_log`
6. `make lint`、`make test`、`npm run build` 全绿

## 边界

- 不做自动重签证书
- 不改 `setup.sh`
