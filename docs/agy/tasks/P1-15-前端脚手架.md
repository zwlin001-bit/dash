# P1-15 前端脚手架与图表组件

> 第一期 · 任务 15/19 ｜ 前置：01 ｜ 分支：`agy/p1-15-web-scaffold`

## 目标

前端工程 + 一个监控和后续测速都要复用的时序图表组件。
**不依赖任何后端接口**，接 mock 数据即可。

## 交付物

```
web/
  构建工具链（TypeScript）
  路由骨架：登录 / 节点总览 / 节点详情 / 机器清单 / 系统设置
  api/         统一的请求封装（鉴权、错误处理、SSE）
  components/
    TimeSeriesChart   ★ 时序图表组件
  mock/        假数据
internal/api/web.go   go:embed 内嵌前端产物
```

★ **开工前先读 [`../../08-field-map.md`](../../08-field-map.md)**，字段名、单位、聚合方式全部以它为准。

## 技术栈（已定，不要自选）

见 [`../../adr/0005-frontend-stack.md`](../../adr/0005-frontend-stack.md)：

```
React 18 + TypeScript + Vite 5
CSS 变量 + CSS Modules（★ 不用 Tailwind、不用组件库）
TanStack Query 5   服务端状态、缓存、请求竞态
React Router 6
Apache ECharts 5   图表
```

全部锁定具体版本，不用 `latest`。

## 设计规格

★ **界面 token、双主题、布局、组件类名全在
[`../../13-ui-spec.md`](../../13-ui-spec.md)，开工前完整读一遍。**

设计稿在仓库里：

```
docs/agy/css/dash2.html    浅色主题参考（侧栏 288 / 顶栏 64 / 毛玻璃）
docs/agy/css/demo2.html    深色主题参考（侧栏 220 / 顶栏 48 / 紧凑）
```

两份是**同一套 token 契约的两个主题**，语义变量名完全一致。

★ **做法：把 demo 的 CSS 变量层原样抽成 `web/src/styles/tokens.css`，组件类名沿用 demo 的命名。**
不要重新发明设计系统，也不要照抄 HTML 结构——demo 是静态稿，实现是 React 组件。

几条硬要求：
- 组件里**不许出现字面量颜色值**，一律走变量
- **每个 token 在浅色和深色下都要有定义**，不许只在一个主题里定义
- 数字一律 `--font-mono`（`cell-mono` 类），表格里数字才能对齐扫读
- **不引入 Web Font**（demo 里的 Geist 不要），中文回退链已排好
- 图表系列色**从 CSS 变量读**（`getComputedStyle`），不在 JS 里写死十六进制，否则切主题不跟随

## 约束

- **前端产物内嵌进 dashd 二进制**（`go:embed`），部署时不需要单独的 web 服务器。
  这是「一条命令部署」的前提
- ★ **时序图表组件监控和测速共用一套**，第二期的测速趋势图会直接复用它。
  入参形状按任务 13 的查询返回定义，**两边定好一次，之后不要各改各的**
- 组件要支持四个跨度（6h / 3d / 60d / 1y）和多指标叠加
- 实时数据走 SSE，**不轮询**
- 不追求好看，追求够用和能复用

## 验收

1. `make build` 后，`bin/dashd` **单文件启动就能打开登录页**（不需要任何外部文件）
2. 图表组件用 mock 数据能渲染四个跨度
3. 图表组件的入参类型定义与任务 13 的接口返回一致（贴出两边的类型对照）
4. 页面路由都能打开（内容可以是空壳）

## 边界

**只做脚手架和组件，接 mock 数据。不接真实接口**（任务 16、17 做）。

### ❌ F1 必须修 —— 组件里有一处字面量颜色

```css
/* TimeSeriesChart.module.css:79 */
.spanBtn.active { background: var(--accent); color: #ffffff; }
```

`13-ui-spec.md` §2 要求「组件里不许出现字面量颜色值，一律走变量」。
`#ffffff` 在暗色主题下恰好也对，所以看不出问题——但这正是这类漏洞难发现的原因。
改成 `var(--white)`（或新增一个 `--on-accent` 语义变量，更准确）。
