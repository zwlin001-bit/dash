### 关键差异（相对第 1 轮）

| | 第 1 轮（已合并） | 本轮 |
|---|---|---|
| 域名 | 1 个 | **2 个** |
| TLS 终结 | dashd 内置 autocert | **nginx** |
| dashd 监听 | `0.0.0.0:443`（setcap） | **`127.0.0.1:8443`**，不再需要 setcap |
| 控制台暴露面 | 公网 | **仅 WireGuard 内网** |
| 依赖 | 无 | **nginx（setup.sh 负责装好配好）** |

### 三个最容易做错的地方

1. ★ **控制台的 nginx server 块必须 `listen <内网IP>:443`，不是 `listen 443`。**
   绑 `0.0.0.0` 等于把控制台重新暴露到公网，这条做错整个架构就没意义了
2. ★ **内网域名不能用 ACME HTTP-01 签证书** —— Let's Encrypt 验证不到内网 IP，
   会一直失败且原因难查。必须 DNS-01 或自签
3. ★ **公网 server 块只放行 `/api/agent/v1/`、`/dl/`、`/install.sh`，其余 `return 404`。**
   验收会实测 `curl https://<公网域名>/` 必须返回 404

### 双域名双入口

| 入口 | 域名 | 绑定 | 用途 |
|---|---|---|---|
| **管理控制台** | 内网域名 | **内网 IP**（WireGuard 网段） | 仅本人访问，走 WG 进来，攻击面最小 |
| **Agent 接入** | 互联网域名 | 公网 | agent 上报与拉取指令 |

- `setup.sh install` **要求输入两个域名**
- 两个域名分别签发证书
- **控制台入口绑内网 IP，不监听公网**——这是这套架构的安全核心
- agent 接入入口只暴露 `/api/agent/v1/*` 与 `/dl/*`，**不暴露控制台 API 和界面**

### nginx + 应用一起发布

`setup.sh install` 直接把依赖装好、配好、起好，用户不需要单独装 nginx。
nginx 负责两个 server 块（内网/公网）与 TLS 终结，dashd 监听本地回环。

### 服务端资源预算

稳态 RSS ≤ 1 GB，1–2 GB 内存的机器能跑。具体见 [`P1-21-dashd主程序装配.md`](P1-21-dashd主程序装配.md)。

## 目标

**用户视角只有一句话：`sudo ./setup.sh install`，只问域名。**

## 交付物

```
setup.sh    子命令：install / upgrade / uninstall / status
systemd unit + OpenRC 脚本
ACME 证书自动申请与续期（autocert）
```

## 约束

- ★ **交互只有一个必填项：域名。** 其余全部有合理默认值
- 非交互：`./setup.sh install --domain x --yes`
- **POSIX sh**，Alpine busybox ash 能跑
- **全部子命令幂等**，可重复执行
- 默认监听 **443**；`setcap cap_net_bind_service=+ep` 后**以非 root 用户 `dashd` 运行**
  （Alpine 需先 `apk add libcap`）。验收会查 `ps -o user=`
- 80 端口只做 ACME HTTP-01 挑战 + 301 跳 443
- ★ **域名写入数据库 `settings.site.domain`，不写配置文件**（P5.4）
- ★ **ADB 已关闭 mTLS，用连接串直连，不需要 wallet。**
  数据库连接信息通过 `--db-dsn` / `--db-user` / `--db-password` 或环境变量提供，
  写入 `/etc/dash/config.toml`（`0600`）
- 落文件：
  ```
  /usr/local/bin/dashd
  /etc/dash/config.toml     0600 dashd:dashd
  /var/lib/dash/            0750 dashd:dashd
  ```
- 安装流程：前置检查 → 建用户 → 落文件 → setcap → 写服务 →
  跑迁移 → 写入域名 → 建管理员 → 启动 → 等 `/healthz` 通过
- **健康检查失败要打印日志尾部**，不要静默失败
- `status` 要显示：服务状态、版本、数据库连通性、证书到期时间、在线 agent 数
- `upgrade` 健康检查失败**自动回滚到旧二进制**
- `uninstall` 默认保留 `/etc/dash` 和数据库，`--purge` 才删配置，**数据库永远不动**
- 安装完成打印：访问地址、初始管理员密码（只显示一次）、
  **需要备份的文件：`/etc/dash/master.key`（若已生成）、`/etc/dash/config.toml`**

## 验收

三个系统各跑一次，PR 里贴输出：

1. Debian / Ubuntu / Alpine 干净环境各跑一次 `install`，装完能用域名 HTTPS 访问
2. **重复执行 `install` 不报错**
3. `ps -o user= -p $(pidof dashd)` **不是 root**
4. `status` 各项都正确
5. `upgrade` 到一个故意坏掉的二进制，**自动回滚**且服务继续可用
6. `uninstall` 后数据库数据仍在
7. `busybox ash -n setup.sh` 语法检查通过

## 边界
