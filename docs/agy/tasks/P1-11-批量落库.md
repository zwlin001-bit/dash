## 算法规格

### 缓冲与刷写

```
ring buffer 容量 = 预期节点数 × (flush 间隔 / fast 间隔) × 4   （默认 4096 行）
flush 触发：每 5 秒，或缓冲达到 80% 容量，两者先到先触发
一次 flush = 两条批量语句（sample_host 一条、sample_dim 一条）
```

- 用 `internal/db` 的 `BatchInsert`，**不要自己拼 SQL**
- flush 期间新到的上报进另一个 buffer（双缓冲），**不加锁等待**

### 计数器 reset 恢复

进程启动时，为每个节点取最近一行的累计值作为 `prev`：

```sql
SELECT node_id, net_total_up, net_total_down, ts_ms
FROM sample_host
WHERE node_id = ? AND ts_ms >= ?
ORDER BY ts_ms DESC
```
取每个节点的第一行（`ts_ms >= 当前时间 - 1 小时`，超过 1 小时的旧值不可信，当作无 prev）。

★ **没有 prev 时，本轮的 `traffic_up/down` 写 NULL，不写全量累计值。**
否则 dashd 一重启，每台机器都会凭空多出一笔等于开机以来总流量的增量。

增量公式（`02-database.md` §5.7）：
```
delta = cur >= prev ? cur - prev : cur
```

### 维度 series

`metric_series` 用 `Upsert`（`node_id, metric_code, dim_key` 为冲突键），
**并在内存里缓存 `(node_id, metric_code, dim_key) → series_id` 的映射**，
稳态下不产生任何 series 查询。缓存在 series 首次出现时才回库。

### 掉批指标

丢批时递增内部计数并 `events.Emit` 一条 `system.db_unreachable`（受 dedup 限制，
不要每 5 秒发一条）。计数暴露在 `/healthz`。

## 约束

- **绝不一条上报一次 INSERT。** ADB 在网络另一端，往返延迟是主要成本。
  30 台 × 5 秒 = 一次 flush 约 30 行主机样本 + 少量维度样本，**两条批量语句搞定**
- 批量写用 `internal/db` 的 `BatchInsert`，**不要自己拼 SQL**
- **flush 失败重试 3 次（退避 1s/2s/4s），仍失败则丢弃最老一批并计数告警。
  绝不允许阻塞采集链路**——监控数据不值得为了不丢而把整条链路堵死
- **最新值内存缓存**：前端实时视图读它，不查库。数据库短暂不可用时实时视图仍要正常
- **计数器 reset 处理（这条不做，机器一重启流量统计就会出天文数字）**：
  ```
  delta = cur >= prev ? cur - prev : cur
  ```
  `net_total_up/down` 是单调累计值，机器重启会归零。
  `prev` 按节点存内存，**进程重启时从数据库最近一行恢复**。
  `traffic_up/down` 存的就是这个 delta，月度流量 = 对区间做 SUM
- 维度指标（每块磁盘、每张网卡）写 `metric_series` + `sample_dim`，
  `metric_series` 用 upsert（走 dialect），不要每次都查一遍

## 验收

1. **30 个模拟 agent 以 5 秒间隔上报 10 分钟**，`sample_host` 行数 = 30 × 120 ± 少量边界
2. **中途断开数据库 30 秒**，恢复后写入继续，**且实时视图全程可用**
3. **模拟机器重启**（`net_total_up` 归零），`traffic_up` 不出现负值、不出现异常巨值
4. dashd 进程重启后，`prev` 从数据库正确恢复，重启前后不产生一个虚假的巨大 delta
5. 灌入超过 buffer 容量的数据，确认是丢最老的那批且有计数，没有阻塞或 panic
6. PR 里贴 ADB 上 `select count(*) from sample_host` 的实际输出

## 边界

不做 rollup（任务 12）、不做查询 API（任务 13）。
