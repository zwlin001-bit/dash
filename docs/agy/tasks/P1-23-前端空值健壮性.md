## 问题

线上 `/machines` 页面**先显示数据、随后整页白屏**。

崩点在 `web/src/pages/Machines/Machines.tsx`：

```js
// :782
(n.billing.expires_at_ms - Date.now()) / 86400000
// :843
{n.group.name}
```

而 API 返回的节点**根本没有 `billing` 和 `group` 这两个字段**——
后端在没配计费信息 / 未分组时用 `omitempty` 直接省略了：

```json
{"id":"01M1XSFHD...","name":"test-vps-1","conn_state":"offline",
 "last_seen_at_ms":1788779939256,"tags":[],"latest":null}
```

`undefined.expires_at_ms` 抛 TypeError，**而全站没有 ErrorBoundary**，
React 18 直接卸载整棵树 → 白屏。

「先有数据后变空白」就是这个过程：首屏空列表不崩 → 数据到达触发重渲染 → 崩 → 白。

★ **这一条的根因在设计侧（我的责任）**：`12-api-spec.md` §4 的示例把 `group`
和 `billing` 写成了始终存在，前端照着实现，后端却按 `omitempty` 省略。
**接口规格已更新**，明确标注了哪些字段可能不存在——本任务以更新后的规格为准。

## 目标

**任何单个组件出错都不能白掉整个应用；所有可选字段都要按「可能不存在」处理。**

## 交付物

```
web/src/components/ErrorBoundary/     错误边界组件
web/src/App.tsx                       路由级 + 应用级两层边界
web/src/pages/**                      修掉全部无保护的可选字段访问
web/src/api/types.ts                  可选字段类型标注为 optional
```

## 约束

### ❶ ErrorBoundary（两层）

- **应用级**：兜底，显示「出错了 + 刷新按钮 + 错误摘要」，**不要白屏**
- **路由级**：单个页面崩掉时，侧栏和顶栏仍在，用户能切到别的页面
- 开发模式下把 `error.stack` 显示出来；生产模式只显示摘要
- ★ 边界要**打 console.error**，方便你我排查

### ❷ 可选字段全量排查

★ **不是只修 782 和 843 两行。** 按 `12-api-spec.md` 把所有可选字段过一遍：

| 字段 | 何时不存在 |
|---|---|
| `node.group` | 节点未分组 |
| `node.billing` | 未配置计费信息 |
| `node.latest` | 节点从未上报 / 离线且缓存已清 |
| `node.latest.*` 各指标 | 采集失败时单项省略 |
| `node.facts` | agent 尚未上报 facts |
| `node.agent_version` | 空字符串（不是 undefined） |
| `node.clock_skew_ms` | 未测得时省略 |
| `series` 里的点 | **可能是 `null`**（缺失点），图表要断线不要连成直线 |

要求：
- TypeScript 类型里标成 `?`，**靠类型系统挡住**，不要只在用的地方加 `?.`
- 数值格式化统一走一个 helper：`fmt(v, unit)` —— `undefined`/`null` 一律显示 `--`
- **不要用 `|| 0` 掩盖缺失**：`0%` 和「没数据」在监控界面上是两回事，
  用户看到 CPU 0% 会以为机器空闲，实际是没采到

### ❸ 顺带

- `tsconfig.json` 打开 `strictNullChecks`（如果还没开），让编译期就能抓到这类问题
- 加一个**空数据快照测试**：用 `{"items":[{"id":"x","name":"n","conn_state":"offline","tags":[]}]}`
  这种最小节点渲染 Machines 与 Overview，断言不抛异常

## 验收

1. ★ **用最小字段的节点数据渲染 `/machines` 与 `/`，页面正常显示，不白屏**
   （可用 mock 或直接对着一个只有 `id/name/conn_state/tags` 的节点）
2. 故意在某个页面组件里 `throw new Error('boom')`，
   **应用不白屏**，显示错误提示且侧栏可用，能切到其他页面
3. 无数据的字段显示 `--`，**不是 `0` 也不是 `NaN` 或 `undefined`**
4. `npm run build` 无 TypeScript 错误
5. 图表遇到 `null` 点断线，不连成直线
6. 空数据快照测试通过

## 边界

不改后端字段是否省略的行为——`omitempty` 是对的，前端本来就该处理缺失。
