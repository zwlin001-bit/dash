## 问题：非默认区域的实例发现不了

用户问「添加云账号的默认扫描区域有什么影响？非默认区域是否可以监测到」。
核对代码，答案是**发现不了**：

| 位置 | 现状 |
|---|---|
| `web/src/pages/Cloud/Cloud.tsx:355` | 前端**硬编码 6 个 region** 传给发现接口 |
| `internal/provider/aliyun/client.go:552` | 后端兜底也只有 8 个 region |
| `cloud_accounts.default_region` | 存了，但**发现时根本不用它** |

所以放在 `eu-central-1`（法兰克福）、`ap-south-1`（孟买）、`ap-southeast-3`（吉隆坡）
这些区域的实例，**扫不出来，也就管不了**。

★ 注意：**只影响「发现」这一步**。一旦资源被发现并入库，
`cloud_resources.region` 记的是它自己的区域，后续查状态、启停、拉指标都用那个，没问题。

## 目标

**区域列表由用户维护，而且能从阿里云拉真实列表，不靠硬编码。**

## 约束

### 区域列表存起来、可编辑

`cloud_accounts.config_json` 里加 `scan_regions: []string`（已有这个列，不用改表）。

- 空数组 = **扫全部可用区域**（见下）
- 界面上是多选，不是单选 —— ★ 现在那个「默认扫描区域」单选框语义就是错的，
  一个账号本来就可能横跨多个区域

### 区域候选从 API 拉

`DescribeRegions` 后端已经实现了（`client.go:217`），但没人调用。

- 添加/编辑账号时调一次，把**真实区域列表**填进多选框
- ★ **带上中文名**（`DescribeRegions` 返回 `LocalName`），
  让用户看到「华东1（杭州）」而不是 `cn-hangzhou`
- 拉不到就退回一份内置清单，并提示「未能获取区域列表，正在使用内置清单」

### 扫全部区域要有护栏

★ 阿里云有 **20+ 个区域**，全扫意味着 20+ 次 `DescribeInstances`。

- 全扫是允许的，但界面上要显示「将扫描 N 个区域，约需 N 次 API 调用」
- ★ **扫描结果里要列出「哪些区域有实例、哪些是空的」**，
  用户看完自然会把空区域取消掉，下次就快了
- 单个区域失败**不中断**其余区域（现在 `client.go` 已经是 `continue`，保持）

### 顺带

- 账号列表页把「默认区域」列改成「扫描区域」，显示 `已选 N 个` 或 `全部`
- ★ **删掉前端那行硬编码的 6 个 region**，`lint` 里加一条禁止在 `web/src` 出现
  形如 `cn-hangzhou` 的区域字面量（区域是数据不是常量）

## 验收

1. 添加账号时区域多选框里是**从 API 拉回来的真实列表**，带中文名
2. ★ 在一个**非默认区域**（如 `eu-central-1`）建一台 ECS →
   勾上该区域后 → **能被发现并纳管**
3. 不勾任何区域 = 全扫 → 界面提示将扫 N 个区域；扫完列出**有实例 / 空**的区域
4. 某个区域凭据无权限 → 该区域跳过并提示，**其余区域照常返回**
5. 编辑账号能改区域列表，改完重新发现生效
6. `web/src` 下 grep `cn-hangzhou` 等区域字面量 **0 命中**
7. `make lint`、`make test` 全绿
