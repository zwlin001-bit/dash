## 约束

- **`cmd/dashd/main.go` 必须预留模块注册接口**。形如：
  ```go
  type Module interface {
      Name() string
      Register(*App) error   // 注册路由、后台任务、依赖注入
  }
  var modules = []Module{ /* 后续任务每人加一行 */ }
  ```
  后续 18 个任务只允许往这个列表加一行，不改装配逻辑。**这条不做好，main.go 会变成冲突重灾区。**

- **必须写一条 lint 规则：`agent/**` 和 `cmd/dash-agent` 不许 import
  `internal/db`、`internal/api`、`internal/control`、`internal/ingest`、`internal/inventory`。**
  agent 只允许 import `internal/protocol`。
  没有这条规则，agent 二进制迟早被服务端依赖撑到几十 MB，直接违反 P3 的体积预算。

- 每个新建目录必须有 `README.md`，写清：职责边界、对外接口、依赖谁（P1.4）

- `.gitignore` 已存在，不要改动 `.secrets/` 那几行

## 验收

1. `make build` 产出 `bin/dashd` 和 `bin/dash-agent`，两个都能 `--version` 正常输出
2. `make lint test` 通过
3. 故意在 `agent/collect/` 里写一行 `import "…/internal/db"`，`make lint` 必须报错
4. 每个目录都有 `README.md`

## 边界

**不写任何业务逻辑。** 不连数据库、不定义协议结构体、不写采集代码。
这个任务的产出应该是「能编译、能跑、什么都不做」。

### ❌ F1 必须修 —— lint 只覆盖直接 import，间接依赖漏检

`scripts/lint-imports.sh` 是 grep 源文件里的 import 行，**挡不住传递依赖**。

实测复现（`agent/collect` → `internal/protocol` → `internal/db`）：

```
./scripts/lint-imports.sh          → ✅ 通过（退出码 0）
go list -deps ./agent/collect      → dash/internal/db     ← 实际被链进 agent 了
                                     dash/internal/protocol
                                     dash/agent/collect
```

这条规则存在的意义是**防止 agent 二进制被服务端依赖撑大**。
只查直接 import 挡不住这件事，而且会给出虚假的安全感——**比没有检查更危险**。

**修法**：改用 `go list -deps` 展开全部传递依赖。

```sh
FORBIDDEN=$(go list -deps ./agent/... ./cmd/dash-agent 2>/dev/null \
  | grep -E '^dash/internal/' \
  | grep -v '^dash/internal/protocol$' || true)
if [ -n "$FORBIDDEN" ]; then
  echo "❌ agent 依赖了服务端包：" >&2
  echo "$FORBIDDEN" >&2
  exit 1
fi
```

原有的 grep 检查可以保留（它能给出具体文件行号，报错更友好），
但 **`go list -deps` 这道必须加上**，且两道都要跑。

**复验必须同时满足**：
- 直接 import 违规 → 报错
- 间接依赖违规（构造上面那条链）→ **也要报错**
