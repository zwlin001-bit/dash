# P1-01 工程骨架与依赖纪律

> 第一期 · 任务 01/19 ｜ 前置：无 ｜ 分支：`agy/p1-01-skeleton`
> 通用约定见 [`../03-rules.md`](../03-rules.md)，硬性约束见 [`../../PRINCIPLES.md`](../../PRINCIPLES.md)

## 目标

搭出所有后续任务都要往里加东西的骨架。**这个任务定型不好，后面 18 个任务都会互相冲突。**

## 交付物

```
go.mod                    Go 1.22+，版本锁死
Makefile                  build / build-agent-all / test / lint / migrate
cmd/dashd/main.go         ★ 模块注册接口
cmd/dash-agent/main.go
internal/{config,logx,db,protocol,control,ingest,api,inventory}/   建目录 + README.md
agent/{collect,transport,runtime}/                                建目录 + README.md
web/                      占位
migrations/               占位
scripts/                  占位
```

## 约束

- **`cmd/dashd/main.go` 必须预留模块注册接口**。形如：
  ```go
  type Module interface {
      Name() string
      Register(*App) error   // 注册路由、后台任务、依赖注入
  }
  var modules = []Module{ /* 后续任务每人加一行 */ }
  ```
  后续 18 个任务只允许往这个列表加一行，不改装配逻辑。**这条不做好，main.go 会变成冲突重灾区。**

- **必须写一条 lint 规则：`agent/**` 和 `cmd/dash-agent` 不许 import
  `internal/db`、`internal/api`、`internal/control`、`internal/ingest`、`internal/inventory`。**
  agent 只允许 import `internal/protocol`。
  没有这条规则，agent 二进制迟早被服务端依赖撑到几十 MB，直接违反 P3 的体积预算。

- 每个新建目录必须有 `README.md`，写清：职责边界、对外接口、依赖谁（P1.4）

- `.gitignore` 已存在，不要改动 `.secrets/` 那几行

## 验收

1. `make build` 产出 `bin/dashd` 和 `bin/dash-agent`，两个都能 `--version` 正常输出
2. `make lint test` 通过
3. 故意在 `agent/collect/` 里写一行 `import "…/internal/db"`，`make lint` 必须报错
4. 每个目录都有 `README.md`

## 边界

**不写任何业务逻辑。** 不连数据库、不定义协议结构体、不写采集代码。
这个任务的产出应该是「能编译、能跑、什么都不做」。
