## 问题：101 个测试从来没跑过

`go test ./...` 现在是全绿的，但那是假象：

```
$ go test ./... -v 2>&1 | grep -c "^--- SKIP"
101
$ go test ./internal/jobs/... -v 2>&1 | grep "^--- SKIP"
--- SKIP: TestAcceptance1_ThreeStepsProgress
--- SKIP: TestAcceptance2_IdempotentStepRetry
... (八条全跳)
```

原因是同一条：`127.0.0.1:33306` 上没有 MySQL。分布：

| 包 | 跳过数 | 覆盖的验收项 |
|---|---|---|
| `internal/alert` | 8 | 去抖、重启恢复 firing、静默窗口、离线、到期、**流量计数器归零不误报**、标签作用域、读 rollup |
| `internal/jobs` | 8 | 断点重试、崩溃恢复、同 target 不并发、超时、取消、worker 上限 |
| `internal/notify` | 6 | 渠道、路由、投递记录 |
| `internal/guard` | 5 | 只监控不动手、演练、月初重置、批量调用次数、通知去重 |
| `internal/cloudmetric` | 5 | 存取、增量、失败隔离、保留期 |
| `internal/db` / `internal/migrate` | 5 | 方言可移植性、迁移一致性 |
| 其余（ingest / counter 等） | 64 | 落库、计数器 reset |

★ **这些恰恰是最该测的部分。** 纯函数逻辑不接触数据库，问题少；
出事的都是状态机、并发、重启恢复、计数器溢出 —— 全在跳过名单里。

★ **而且它「绿着骗人」比没有测试更危险**：验收时看到 `ok dash/internal/jobs`
会以为验过了。这个坑我自己已经踩过一次
（P2-03 第 1 轮验收记录里误报「全部实跑通过」，实际全跳）。

## 目标

**让 `go test ./...` 在任何一台开发机上都能真的跑完，而不是跳过一大半。**

## ❶ 一条命令起测试库

```
make test-db-up      # 起一个一次性 MySQL 在 33306
make test-db-down    # 停掉并清干净
make test            # 依赖 test-db-up
```

实现方式**自己选**，在交付说明里写清理由。三个方向：

- **A. Docker/Podman 容器**：最简单，但要求机器有容器运行时
- **B. 系统包装的 mariadb/mysql**，用独立 datadir + 独立端口起一个实例，
  不碰系统已有的服务
- **C. 内嵌**：把 DB 相关测试改用 SQLite 内存库

★ **C 要慎重**：`PRINCIPLES.md` 要求 SQL 只写可移植方言（Oracle → MySQL），
用 SQLite 跑测试会让「方言可移植」这件事失去验证意义 ——
`internal/db` 和 `internal/migrate` 那 5 个测试**本来就是在验方言**。
如果选 C，这两个包必须仍然走真实 MySQL。

## ❷ 跳过要吵，不要静悄悄

现在跳过是无声的，`go test ./...` 照样报 `ok`。改成：

- ★ **默认跳过时打印醒目汇总**：跑完在末尾输出
  「⚠️ 本次有 N 个测试因缺少测试数据库被跳过，跑 `make test-db-up` 后重试」
- ★ **`make test` 里设 `DASH_REQUIRE_TEST_DB=1`**，此时**跳过一律变成失败**。
  CI 与验收走这条路径，个人本地随手跑可以不设

## ❸ 把积压的验收补跑一遍

- `make lint` 或提交前检查里加一条：**新增 `t.Skip` 必须说明理由**，
  不许再出现「缺依赖就静默跳过」的新用法
- `docs/agy/03-rules.md` 写清：DB 相关测试怎么写、怎么本地跑

## 验收

1. ★ 干净机器上 `make test-db-up && make test` → **`--- SKIP` 数量为 0**
2. `make test-db-down` 后再跑 → 有醒目的跳过汇总，不是静悄悄的 `ok`
3. ★ `DASH_REQUIRE_TEST_DB=1 go test ./...` 在没有库时 **失败**，不是通过
4. `internal/db` 与 `internal/migrate` 的方言测试跑在**真实 MySQL** 上
   （若选方案 C 也必须如此）
5. 五个包的积压验收全部补跑，结果写回各自任务书
6. 测试库与开发者本机已有的 MySQL/生产库**完全隔离**：
   独立端口、独立 datadir，`make test-db-down` 后不留残留
7. 连跑两次 `make test-db-up` 幂等，不会因为已存在而失败
8. `make lint`、`make test` 全绿

## 边界

- 不引入 CI 系统
- 不改任何业务代码（❸ 发现的问题记录后交回验收）
- 不改 Oracle 侧的测试策略（Oracle ADB 没法本地起，维持现状）
