# P2-16 CDT 境内 / 海外分区额度与停止线

> 第二期 · 任务 16 ｜ 前置：P2-04 ✅ **P2-11**（账号级策略）｜ 分支：`agy/p2-16-cdt-zones` ｜ **预计一天**

> ★ **完成后必须自己 `git push -u origin <分支名>`**。

## 现有模型是错的

P2-02 / P2-04 把 CDT 流量当成**账号级一个数字**。实际不是：

★ **阿里云 CDT 的免费额度按「中国内地」与「中国香港及海外」分开计算**：

| 区域组 | 免费额度 | 停止线（可配） |
|---|---|---|
| 中国内地 | **20 GB / 月** | 默认 20 GB |
| 中国香港及海外 | **200 GB / 月** | 默认 200 GB |

两个额度**互不相通**：境内用爆了，海外的 200 GB 一点都补不上。
现在把两者加总成一个数去比一个阈值，**必然误判** ——
海外用了 150 GB、境内用了 25 GB，加起来 175 GB 看着"没超"，
但境内其实早就超额计费了。

★ **海外可能有多台服务器**，它们共享同一个 200 GB 池子。

## 目标

**按区域组分别统计、分别设停止线、分别决策。**

## ❶ 区域分组

新增一张映射表（或代码内常量 + 可覆盖配置，二选一，在交付说明里写理由）：

```
cdt_zone = "cn"   →  region 前缀 cn-*，但 ★ 不含 cn-hongkong
cdt_zone = "intl" →  cn-hongkong 及其余全部
```

★ **`cn-hongkong` 归 intl 是最容易搞错的一条**，阿里云自己的口径就是
「中国香港及海外」。写死在代码里并加注释，再加一条单元测试钉住。

区域到组的映射要**可覆盖**（配置里能改），因为阿里云偶尔会调整口径。

## ❷ 拆流量统计

`ListCdtInternetTraffic` 返回的 `TrafficDetails` 里带区域信息 ——
★ **不要只 `sum(Traffic)` 就完事**（`P2-02` 现在就是这么做的），
要按区域分组求和，产出两个数：`cn_used_gb` 与 `intl_used_gb`。

★ 如果返回项里拿不到区域，**记为 `unknown` 单独一组并告警**，
不许静默塞进任何一边 —— 塞错一边就是误判停机。

## ❸ 策略与决策

在 P2-11 的 `guard_account_policies` 上，把单一阈值拆成两个：

```
traffic_limit_cn_gb    f64 NULL   -- 默认 20
traffic_limit_intl_gb  f64 NULL   -- 默认 200
warn_ratio             f64        -- 两组共用，默认 0.8
```

决策规则：

- ★ **一台实例只看它自己所在区域组的用量与阈值**，不看另一组
- 境内组超线 → 只停境内的实例；海外组超线 → 只停海外的实例
- ★ **两组互不影响。** 境内爆了不许去停海外的机器
- 设备级覆盖（P2-11 的 `inherit_account`）继续有效，覆盖的是**它所属那组**的阈值

★ **P2-04 §2 的四条安全性质在每一组内部都必须继续成立**，
尤其「读不到流量不许启动」—— 某一组的流量读失败时，
**只冻结那一组的启动，另一组照常工作**。

## ❹ 界面

守卫页的账号卡片从一条进度条改成**两条**：

```
中国内地    ▓▓▓▓▓░░░░░  12.4 / 20 GB   (62%)
中国香港及海外 ▓▓▓▓▓▓▓▓░░  168 / 200 GB  (84%)  ⚠️
```

- 每条独立着色：≥80% 橙（`--warn`），≥100% 红（`--err`）
- ★ **实例列表按区域组分节展示**，让人一眼看出哪台算在哪个池子里
- 阈值在界面上可改，改完立即回显新的百分比
- 颜色走 token

## ❺ 事件

预警与停机事件的 `payload_json` 里★ **必须带 `cdt_zone`**（`cn` / `intl`），
否则收到「流量达阈值已停机」根本不知道是哪个池子爆了。

`dedup_key` 加上区域组：`guard:acct:<account_id>:<event_type>:<zone>:<月份键>`
—— 否则境内先超额、海外后超额，第二条会被当成重复吞掉。

## 验收

1. ★ 造一个「境内已用 25 GB / 海外已用 10 GB」的场景 →
   **只有境内的实例被停**，海外实例不受影响
2. 反过来「境内 5 GB / 海外 210 GB」→ **只停海外的**
3. ★ `cn-hongkong` 的实例被算进 **intl** 组（有单元测试钉住）
4. 两条进度条各自独立着色，84% 显示橙色警示
5. 阈值改成境内 10 GB → 下一轮按新阈值决策
6. ★ CDT 返回里某项没有区域信息 → 记为 `unknown` 并**发告警**，
   不被塞进任何一组
7. 只有境内组的流量查询失败 → **境内组不启动实例、海外组照常工作**
8. 境内与海外先后超额 → **收到两条通知**，不被去重吞掉
9. 事件 `payload_json` 里有 `cdt_zone`
10. `make lint`、`make test` 全绿

## 边界

- 不做按实例的流量配额（CDT 本来就没有这个粒度）
- 不做超额后的费用估算
