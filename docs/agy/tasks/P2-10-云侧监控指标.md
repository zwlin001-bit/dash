## 三个 agent 拿不到的场景

1. ★ **被保活停掉的实例**（P2-04）—— 机器关着 agent 就不在跑，
   界面上只能显示 `--`。但你恰恰想知道它停之前用了多少
2. **装不上 agent 的资源** —— RDS、SLB、OSS、公网带宽包
3. ★ **账号级 CDT 流量没有历史** —— P2-04 每轮查一次当前值用于决策，**但不落库**。
   于是看不到「这个月烧得多快」，而这正是保活阈值该定多少的依据

★ **这不是要取代 agent。** agent 是 5 秒粒度、指标全、免费；
云监控 1 分钟起步、指标少、调用要计费。**能用 agent 的一律用 agent。**

## 约束

### 表

```
cloud_samples(cloud_account_id, res_ref str(191), metric_code str(40),
              ts_ms ts, value f64,
              PK(cloud_account_id, res_ref, metric_code, ts_ms))
  ix_cloud_samples_ts (ts_ms)
```

- ★ **用 `res_ref`（云厂商侧 id）而不是 `cloud_resource_id`**。
  资源在本地被删了，历史数据不该跟着消失。账号级指标用 `_account` 作 `res_ref`
- ★ **不做多级 rollup。** 云监控本来就 1 分钟起步、数据量比 agent 小两个数量级，
  再分层是过度设计。原始粒度 5 分钟，保留 90 天，走已有的分块清理

### 指标命名：不许另起一套

★ `metric_code` **沿用 `08-field-map.md` 里已有的名字**
（`cpu_pct` / `mem_used` / `net_up_bps` / `net_down_bps` / `traffic_month_up` …）。

同一个 CPU 使用率在 agent 侧和云侧叫不同名字，图表和告警规则就得写两遍。
**provider 负责把厂商的名字翻译成我们的**，这是 provider 该干的活。

### Provider 契约加 `metric.list`

按 `16-cloud-metrics.md` §3 的形状实现，并**同步写进 `01-architecture.md` §3.3 的方法表**
（`CLAUDE.md` 要求改协议必须同步改文档）。

### 拉取策略

- 走 Job 引擎（P2-03），job kind = `cloud.metric.sync`，默认 10 分钟一轮
- ★ **只拉「有人看」的**：默认只拉**被保活规则管着的实例** + **账号级 CDT 流量**。
  全量拉是要花钱的，且大部分资源根本没人看。要拉更多由用户显式勾选
- 增量：记 `(res_ref, metric_code)` 的 `last_at_ms`，只拉之后的点
- ★ 云监控 API 有限流，**串行 + 退避**，某个资源失败**不阻塞其他资源**

### 界面

- 资源详情页：云侧曲线与 agent 曲线**并排但明确区分来源**，
  ★ 标注「云监控 · 5 分钟粒度」。**不要混进同一条线**让人分不清哪个数是哪来的
- ★ **账号页加 CDT 流量月度曲线 + 阈值横线** —— 这是本任务最实用的一张图，
  直接回答「这个月烧得多快、离阈值还有多远」
- 缺数据显示 `--`，断点断线不连成直线
- 颜色走 token（`lint-css-tokens` 会拦）

## 验收

1. ★ **停掉一台被保活管着的实例** → 等一轮同步 → 资源详情页上
   **仍能看到它停机前的 CPU/流量曲线**，不是一片 `--`
2. ★ **账号页的 CDT 流量月度曲线有数据**，且与 P2-04 守卫页显示的当前用量对得上
3. 曲线上明确标着数据来源与粒度，agent 曲线与云侧曲线不混线
4. 跑一轮同步 → 再跑一轮 → ★ **第二轮只拉增量**（调用次数或日志能证明）
5. 未被保活规则覆盖的实例 → **默认不拉**，云监控调用次数不随资源总数线性增长
6. 把云监控权限去掉 → 拉取失败写事件，★ **保活与账单同步不受影响**
7. `metric_code` 与 `08-field-map.md` 一致 —— grep 对照，没有云侧专有的新名字
8. 90 天前的数据被清理任务删除
9. `01-architecture.md` §3.3 的方法表里有 `metric.list`
10. `make lint`（含 SQL 方言与 CSS token）、`make test` 全绿
