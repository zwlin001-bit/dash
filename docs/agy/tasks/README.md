# 第一期任务清单

**第一期只做两件事：监控信息、机器清单维护。**
参考 komari 取其核心（agent 上报），其余按 `docs/` 的设计重做。

## 怎么用

- **一个文件一个任务，按编号从 01 顺序做下去。**
- 每个任务文件是自包含的：目标、交付物、约束、验收都在里面。
  设计文档只在需要背景时才去翻。
- 每个任务开工前还要读这几份（只读一次，后面就熟了）：
  - [`../../PRINCIPLES.md`](../../PRINCIPLES.md) —— 硬性约束
  - [`../03-rules.md`](../03-rules.md) —— 通用工程约定（依赖纪律、测试、日志、提交规范）
  - [`../../08-field-map.md`](../../08-field-map.md) —— **跨层字段总表**，
    任务 04 05 06 11 12 13 15 必读，它是各层不跑偏的唯一保障
  - [`../../10-schema-spec.md`](../../10-schema-spec.md) —— **表结构规格**，
    任务 04 11 12 13 14 20 必读，逐列的类型可空索引都在里面，照抄即可
  - [`../../11-collect-spec.md`](../../11-collect-spec.md) —— **采集算法规格**，任务 06 08 必读
  - [`../../12-api-spec.md`](../../12-api-spec.md) —— **接口规格**，任务 10 13 14 16 17 20 必读
  - [`../../13-ui-spec.md`](../../13-ui-spec.md) —— **界面规格**，任务 15 16 17 必读；
    设计稿在 `docs/agy/css/dash2.html`（浅色）与 `demo2.html`（深色）
- **一次只做一个任务。** 不要顺手做后面的。

## 并行执行

**`01 → 03 → 04` 做完后，可以并行，但不是全部放开。** 实际的波次：

| 波次 | 可同时开工 | 说明 |
|---|---|---|
| 地基 | `01` → `03` → `04` | **必须串行**，一个人做完再放人进来 |
| A | `02` `05` `06` `12` `13` `15` `20` | **7 个并行** |
| B | `07` `10` `14` `16` `19` | 5 个并行 |
| C | `08` `11` `17` | 3 个并行 |
| D | `09` | |
| E | `18` | |

地基之后还剩 **5 层深度**，卡在最长的那条链上：`05 → 07 → 08 → 09 → 18`。
想压时间就优先保这条链，其他慢一点不影响总工期。

### 并行时必须遵守

| 文件 | 规则 |
|---|---|
| `internal/protocol/` | 任务 05 定稿后**锁定**。要改协议 → 停下上报，不要自己改 |
| `migrations/0001_init.*.sql` | 任务 04 定稿后**锁定**。要加表加列 → 申请新编号 |
| `cmd/dashd/main.go` | 只允许加一行模块注册（任务 01 已留好接口） |
| `Makefile` | 只允许追加 target |
| `go.mod` | 冲突直接 `go mod tidy` 重生成，不手工合并 |
| `PRINCIPLES.md` | 谁都不许改 |

一个任务一个分支：`agy/p1-13-query-api`。**不要多个任务共用一个分支。**

### ★ 并行最容易翻车的两处

跨任务的接口如果两边各写各的，一定对不上。这两处**已经在
[`../../08-field-map.md`](../../08-field-map.md) 里钉死了**，并行开发时两边都必须照它写：

1. **`13 查询 API` 的响应 ↔ `15 图表组件` 的 props** —— 见 `08-field-map.md` §4
2. **`06 采集层` 的字段 ↔ `05 协议` 的字段 ↔ `04` 的表列 ↔ `11` 的落库 ↔ `12` 的 rollup 聚合**
   —— 见 `08-field-map.md` §1–§3

**这两处任何一方想改，都要先改 `08-field-map.md`，不许私下对齐。**

## ★ 这一批最容易翻车的三处

1. **CDT 流量是账号级的，不是实例级的。** 同一对 AK/SK 下所有实例共享这个数字。
   按实例循环去查会又慢又触发限流。P2-02 §3 和 P2-04 §1 两边都写了，两边都要照做
2. **凭据明文绝不能落到 dashd 之外。** AK/SK 有启停生产机器的权力，
   不进日志、不进环境变量、不进 API 响应、不进错误信息
3. **保活会真的关掉生产机器。** 默认 `actions_enabled = false`，
   演练模式和二次确认都不是可选项
