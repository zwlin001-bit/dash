# P1-10 服务端 Agent 接入与在线状态

> 第一期 · 任务 10/19 ｜ 前置：04、05 ｜ 分支：`agy/p1-10-control`
> 设计依据：[`../../04-protocol.md`](../../04-protocol.md) §1、§5、§6

## 目标

agent 能连上来、能被认出来、在线状态是准的。

## 交付物

```
internal/control/
  ws.go        /api/agent/v1/rpc WebSocket 端点
  fallback.go  /api/agent/v1/report HTTP 回退端点
  registry.go  在线连接注册表
  enroll.go    /api/agent/v1/enroll 注册端点
  hello.go     agent.hello 处理与参数下发
  README.md
```

## 约束

- **enrollment token**：一次性、15 分钟有效、可预绑定节点名与分组。用过即作废
- **长期 token 只存哈希**（`nodes.agent_token_hash`），明文只在签发那一刻返回一次。
  吊销 = 置空该列
- **`agent.hello` 的应答里下发采集参数**（`interval_fast_s` / `interval_slow_s` /
  `collect_conns` / `need_facts` 等）。**服务端是采集配置的权威**，agent 本地配置只是兜底
- `need_facts`：比对 agent 报上来的 `facts_hash` 与 `node_facts.facts_hash`，
  不一致才要求上报 facts
- **同一 node 重复连接要踢掉旧连接**，否则重连风暴会堆积僵尸连接
- **90 秒没收到任何消息（含 ping）判离线**，更新 `nodes.conn_state` 与 `last_seen_at_ms`
- **时钟偏差**：`server_ts_ms - ts_ms` 超过 60 秒时以服务端时间入库，并在节点上打标记。
  VPS 时钟跑偏很常见，不处理会导致图表出现来自未来或远古的点
- token 无效返回 `-32000`，协议版本不兼容返回 `-32001`
- 注册与吊销**写审计日志**

## 验收

1. 生成 enrollment token → agent 注册成功 → 建出 `nodes` 行 → 返回长期 token
2. **同一个 enrollment token 再用一次被拒**
3. 吊销长期 token 后，agent 收到 `-32000` 并停止重连
4. `kill -9` 掉 agent，**90 秒内**节点标记为离线
5. agent 重启后自动恢复在线
6. 同一节点开两个 agent 进程，旧连接被踢掉
7. 把 agent 机器时间调快 10 分钟，入库时间仍然正确且节点上有时钟异常标记

## 边界

**只管连接、认证、在线状态。指标落库是任务 11 的事**，这里收到 `agent.metrics` 先丢弃或打日志。
