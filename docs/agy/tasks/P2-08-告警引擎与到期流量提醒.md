## 约束

### 一套表装四种规则

`07-monitoring.md` §2.1 写得很清楚：`metric` / `offline` / `expiry` / `traffic`
**共用同一张 `alert_rules` 表和同一个状态机**。

★ **不要拆成四张表、四个评估器。** 它们的去抖、静默、通知、恢复逻辑完全一样，
拆开就是把同一个状态机写四遍。

### 从 rollup 读，不从 raw 读

★ `metric` 类一律读 `sample_host_1m` / `sample_dim_1m`。
raw 是 5 秒粒度，CPU 瞬时尖峰会造成大量误报，1 分钟均值才是「持续高负载」的正确判据。

### 状态机

```
        越界
  ok ─────────▶ pending ──── 持续满 duration_s ────▶ firing
   ▲              │                                    │
   │              │ 恢复正常                            │ 恢复正常
   └──────────────┘                                    │
   └────────────────── resolved ◀───────────────────────┘
```

- ★ **`pending` 不发通知**，只有转 `firing` 才发。这一条是「不被告警淹没」的关键
- `firing → resolved` **要发恢复通知**，否则用户不知道问题过去了
- `silence_s` 内同一 `(rule, node)` 不重复通知，**但事件照样记录**
- ★ **进程重启后必须从 `alert_events` 恢复 firing 状态**。
  不恢复的话，重启会重复告警，而且已经 firing 的问题恢复时不会发恢复通知

### 评估频率

| rule_kind | 频率 |
|---|---|
| `metric` | 每分钟 |
| `offline` | 每 30 秒 |
| `expiry` / `traffic` | 每小时 |

### 作用域

`scope_kind`：`all` / `group` / `tag` / `node`。
★ **标签作用域是最常用的** ——「所有打了 `proxy` 标签的机器，丢包率 > 5% 告警」。
实现时不要只做 `node` 就交差。

### 到期提醒（§4.1）

- 数据源 `node_billing.expires_at_ms`
- ★ **内置三条默认规则**：提前 30 天（info）、7 天（warning）、1 天（critical）
- `is_auto_renew=1` 的节点**默认不提醒**，规则里可开关

### 流量提醒（§4.2）

- 数据源：当前计费周期内 `sample_host_1h` 的 `traffic_up_sum` / `traffic_down_sum` 累加
- 周期起点 `node_billing.traffic_reset_day`
- 口径按 `node_billing.traffic_limit_kind`：`sum` / `max` / `min` / `up` / `down`
- ★ **依赖计数器 reset 处理**（`02-database.md` §5.7）。
  那一步做错，机器一重启这里立刻误报「流量超限」——**验收项 7 专门测这个**

### 接通知

- 规则通过 `alert_rule_channels` 绑定到 P2-01 的 `notify_channels`
- 事件类型按 `09-events-notify.md` §2.1 登记：`alert.firing` / `alert.resolved`
- ★ **`dedup_key` 用 `alert:<rule_id>:<node_id>:<fired_at 的小时>`**，
  配合 `silence_s` 双重保险

## 验收

1. 建一条「CPU > 90 持续 120 秒」的规则 → 把某台机器 CPU 压满 →
   **120 秒后**才收到通知，压满瞬间不发（`pending` 不通知）
2. CPU 降下来 → **收到恢复通知**
3. ★ 规则处于 `firing` 时重启 dashd → **不重复告警**；随后恢复正常 →
   **仍能发出恢复通知**（证明状态从库里恢复了）
4. `silence_s=3600` 时连续越界一小时 → **只收 1 条**，但 `alert_events` 里事件齐全
5. 拔掉 agent → `offline` 规则在 30~60 秒内触发
6. 造一个 3 天后到期的 `node_billing` → 收到 7 天档的 warning，不收 30 天档的重复告警
7. ★ **重启一台机器**（计数器归零）→ **不许误报流量超限**
8. 标签作用域：给两台机器打 `proxy` 标签，规则 scope=tag → **只有这两台触发**
9. `metric` 规则读的是 `_1m` 表，不是 raw —— 查询语句里能看出来
10. `make lint`、`make test` 全绿
