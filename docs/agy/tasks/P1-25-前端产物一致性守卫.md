## 目标

**前端源码与内嵌产物不一致时，`make lint` / `make build` 直接失败。**

## 交付物

```
scripts/lint-dist.sh      一致性检查
Makefile                  接进 lint 与 build
```

## 约束

### 检查方式：内容指纹，不用时间戳

★ **不要比较 mtime** —— git checkout 会重置文件时间，同一份代码在不同机器上
mtime 完全不同，会误报。

用**内容哈希**：

```sh
# 对构建输入取指纹（源码 + 配置 + 锁文件）
FINGERPRINT=$(find web/src web/index.html web/vite.config.ts web/tsconfig.json \
                   web/package.json web/package-lock.json -type f 2>/dev/null \
              | sort | xargs sha256sum | sha256sum | cut -c1-16)
```

`make build-web` 构建成功后，把指纹写进 `internal/api/dist/.build-fingerprint`。
`lint-dist.sh` 重算并比对，不一致就失败：

```
❌ 前端产物与源码不一致
   web/src 指纹: a1b2c3d4e5f6a7b8
   dist 记录的:  0f1e2d3c4b5a6978
   请执行: make build-web
```

### 要点

- ★ **`make build` 必须依赖这个检查**，不能只挂在 `lint` 上 ——
  很多人只跑 build 不跑 lint
- **没有 node/npm 的机器上要能优雅降级**：检测不到 npm 时，
  检查仍然执行（比对指纹），只是**报错信息里说明「本机无 npm，请在有 Node 的机器上构建」**，
  而不是直接跳过。跳过等于没有这道防线
- `.build-fingerprint` 要入库（它是产物的一部分）
- 指纹只覆盖**影响构建输出的文件**，不要把 `web/test/`、`web/scripts/` 算进去，
  否则改测试也要重新构建，徒增摩擦

### 顺带：一次性修掉当前的不一致

本任务同时要跑一次 `make build-web`，把 `internal/api/dist` 更新到与当前
`web/src` 一致并提交。★ **提交前用这条确认**：

```sh
grep -c "ErrorBoundary (" internal/api/dist/assets/*.js   # 必须 > 0
```

## 验收

1. 干净仓库上 `make lint` 与 `make build` **通过**
2. 随便改一行 `web/src/**/*.tsx`（不重新构建）→ `make build` **失败**，
   错误信息明确提示跑 `make build-web`
3. 跑 `make build-web` 后 → `make build` **恢复通过**
4. 只改 `web/test/` 下的文件 → **不触发失败**（不影响构建输出）
5. `internal/api/dist/assets/*.js` 含 `ErrorBoundary (`，即产物已是最新
6. `.build-fingerprint` 已入库

## 边界

不改构建工具链本身，只加一致性校验。

### F1 · 指纹跨机不稳定（已修）

`compute_fingerprint()` 里的 `sort` **依赖 locale**，同一棵树在两台机器上算出不同指纹：

```
zh_CN.UTF-8  → 6d2289319cb0a690
LC_ALL=C     → 7a50404c8a1d48a1
```

验收机装了 `zh_CN.UTF-8`、VPS 没装（退回 C），于是守卫在 VPS 上误报
「前端产物与源码不一致」。★ **这正是任务书里警告过的「同一份代码在不同机器上会误报」，
只是原因从 mtime 变成了 collation。**

修复：`find` / `sort` / `xargs` / `sha256sum` 全程锁 `LC_ALL=C`，并改用 `-print0`/`-0`
避免文件名含空格时出错。已验证三种 locale 下指纹一致。

### F2 · 守卫可被 `setup.sh upgrade` 绕过（已修）

`cmd_upgrade` 找不到现成二进制时会执行裸 `go build ./cmd/dashd`，**绕过 Makefile 也就绕过了本守卫** ——
`web/src` 改了但 `internal/api/dist` 是旧的，照样能编译部署上去，正是本任务要防的场景。
已在自编译前插入 `lint-dist.sh` 调用，不一致则中止升级。

更硬的做法（把指纹带进二进制、`status` 能看出线上跑的是不是当前前端）转入 P1-27。
