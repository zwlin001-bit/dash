## ❷ 开发免登录模式

调试时反复登录很烦，但**不能牺牲生产安全**。

### 设计

配置项 `server.dev_no_auth`（默认 **false**），只能从配置文件或环境变量开：

```toml
[server]
dev_no_auth = true   # ★ 仅供开发调试
```

开启后：鉴权中间件放行所有请求，并把当前用户视为管理员。

### 硬性约束

★ 这是个**故意打开的后门**，必须做到「不可能被误开在生产上」：

1. **默认关闭**，配置文件里不写就是关
2. ★ **`setup.sh` 生成的 `config.toml` 里绝不写这一项** ——
   连注释掉的示例都不要有，避免有人手一滑取消注释
3. ★ **开启时每次启动打印醒目警告**，并且**每处理一个请求就在日志里标记一次**
   （用 `logx.Warn`，加 `dev_no_auth=true` 字段），让人不可能忽略：
   ```
   ⚠️⚠️⚠️  DEV_NO_AUTH 已开启：所有 API 无需登录即可访问
   ⚠️⚠️⚠️  这是开发模式，绝不可用于生产环境
   ```
4. ★ **`/healthz` 里暴露 `dev_no_auth: true`**，
   这样 `setup.sh status` 和外部监控能发现它被误开
5. **前端也要有可见提示**：开启时页面顶部显示常驻横幅
   「开发模式：鉴权已关闭」，用 `--warn` 色，**不可关闭**
6. 编译期不做区分（不用 build tag），保持单一二进制 ——
   靠上面五条运行期防线

### 为什么不用 build tag

单二进制是本项目的核心约束（P3、P5）。为调试模式分裂出第二种产物，
会带来「测的和发的不是同一个二进制」的风险，得不偿失。
代价是后门存在于生产二进制里，**所以上面的防线一条都不能省**。

## 验收

### 总览

1. 起 dashd + 至少一个真实 agent，总览页显示的 CPU/内存/网速**与 agent 真机数据吻合**
2. 断开 agent → 界面在 90 秒内显示离线，**数值变 `--` 而不是停在旧值**
3. 掐断 SSE（防火墙挡掉或关掉服务端推送）→ 界面显示「已断开」并降级为轮询
4. 全仓库 grep `mock`（排除 `web/test/`、`scripts/`）→ **0 命中**

### 开发模式

5. `dev_no_auth` 不配置时 → 行为与现在完全一致，未登录 401
6. 配 `dev_no_auth = true` → 未登录也能访问全部 API；
   **启动日志有警告**；`/healthz` 返回 `"dev_no_auth": true`；
   **前端顶部有常驻横幅**
7. ★ `setup.sh install` 生成的 `config.toml` 里 **grep `dev_no_auth` 为 0 命中**
8. 关掉后重启 → 恢复鉴权

## 边界

不做多用户与权限分级。
