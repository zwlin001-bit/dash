# P1-05 协议契约

> 第一期 · 任务 05/19 ｜ 前置：01 ｜ 分支：`agy/p1-05-protocol`
> 设计依据：[`../../04-protocol.md`](../../04-protocol.md)

## 目标

agent 与服务端共享的协议结构体。**这个包定稿后，agent 和服务端就彻底解耦了。**

## 交付物

```
internal/protocol/
  version.go     ProtocolVersion = 1
  rpc.go         JSON-RPC 2.0 信封：Request / Response / RPCError
  agent2srv.go   agent.hello / agent.metrics / agent.facts
  srv2agent.go   server.config
  errors.go      -32000 ~ -32004 错误码常量
  README.md
```

**第一期只实现上面这几个方法。** `agent.result` / `agent.ping_result` /
`agent.speedtest_result` / `server.exec` / `server.upgrade` 等**只定义常量占位，不定义结构体**——
用不到的结构体现在定了，第二期一定要改。

字段定义严格照 [`../../04-protocol.md`](../../04-protocol.md) §2.1、§2.2、§2.3、§3。

★ **同时必须对照 [`../../08-field-map.md`](../../08-field-map.md)** —— 那是跨层字段的唯一对照表，任何一层对不上都是静默 bug。

## 结构体定义（照这个写）

本节是 `04-protocol.md` §2–§3 的精确化。**两者冲突时以本节为准，并回改 `04-protocol.md`。**

```go
package protocol

const ProtocolVersion = 1

const (
    MethodAgentHello   = "agent.hello"
    MethodAgentMetrics = "agent.metrics"
    MethodAgentFacts   = "agent.facts"
    MethodServerConfig = "server.config"
)

// ---- JSON-RPC 2.0 信封 ----

type Request struct {
    JSONRPC string          `json:"jsonrpc"`          // 恒为 "2.0"
    Method  string          `json:"method"`
    Params  json.RawMessage `json:"params,omitempty"`
    ID      *int64          `json:"id,omitempty"`     // nil = notification
}

type Response struct {
    JSONRPC string          `json:"jsonrpc"`
    ID      *int64          `json:"id,omitempty"`
    Result  json.RawMessage `json:"result,omitempty"`
    Error   *RPCError       `json:"error,omitempty"`
}

type RPCError struct {
    Code    int             `json:"code"`
    Message string          `json:"message"`
    Data    json.RawMessage `json:"data,omitempty"`
}

// ---- agent.hello（request，连接后第一条）----

type HelloParams struct {
    ProtocolVersion int      `json:"protocol_version"`
    AgentVersion    string   `json:"agent_version"`
    BootAtMs        int64    `json:"boot_at_ms"`
    Capabilities    []string `json:"capabilities"`     // 第一期恒为 ["metrics","facts"]
    FactsHash       string   `json:"facts_hash"`
}

type HelloResult struct {
    NodeID            string `json:"node_id"`
    ServerTimeMs      int64  `json:"server_time_ms"`
    IntervalFastS     int    `json:"interval_fast_s"`
    IntervalSlowS     int    `json:"interval_slow_s"`
    FactsMaxIntervalS int    `json:"facts_max_interval_s"`
    CollectConns      bool   `json:"collect_conns"`
    NeedFacts         bool   `json:"need_facts"`
}

// ---- agent.metrics（notification，fast 档每轮一条）----
// ★ 所有指标字段都是指针 + omitempty：采集失败时省略，不是填 0

type MetricsParams struct {
    TsMs     int64       `json:"ts_ms"`
    CPUPct   *float64    `json:"cpu_pct,omitempty"`
    MemUsed  *int64      `json:"mem_used,omitempty"`
    SwapUsed *int64      `json:"swap_used,omitempty"`
    Load     *[3]float64 `json:"load,omitempty"`       // load1, load5, load15
    Net      *NetReport  `json:"net,omitempty"`
    UptimeS  *int64      `json:"uptime_s,omitempty"`
    Slow     *SlowReport `json:"slow,omitempty"`       // 只在 slow 周期到期那轮出现
}

type NetReport struct {
    UpBps     *int64 `json:"up_bps,omitempty"`
    DownBps   *int64 `json:"down_bps,omitempty"`
    TotalUp   *int64 `json:"total_up,omitempty"`
    TotalDown *int64 `json:"total_down,omitempty"`
}

type SlowReport struct {
    DiskUsed  *int64      `json:"disk_used,omitempty"`
    ProcCount *int32      `json:"proc_count,omitempty"`
    TCPCount  *int32      `json:"tcp_count,omitempty"`
    UDPCount  *int32      `json:"udp_count,omitempty"`
    Disks     []DiskEntry `json:"disks,omitempty"`
    NICs      []NICEntry  `json:"nics,omitempty"`
}

type DiskEntry struct {
    Key   string `json:"k"`              // 挂载点，如 "/"
    Used  *int64 `json:"used,omitempty"`
    Total *int64 `json:"total,omitempty"`
}

type NICEntry struct {
    Key       string `json:"k"`          // 网卡名，如 "eth0"
    TotalUp   *int64 `json:"total_up,omitempty"`
    TotalDown *int64 `json:"total_down,omitempty"`
}

// ---- agent.facts（notification）----
// 字段与 node_facts 表对应，见 10-schema-spec.md §2
// ★ 不含 ipv4/ipv6：agent 不查公网 IP，由服务端从连接来源记录（11-collect-spec.md §9.3）

type FactsParams struct {
    Arch       string `json:"arch,omitempty"`
    OSName     string `json:"os_name,omitempty"`
    OSVersion  string `json:"os_version,omitempty"`
    Kernel     string `json:"kernel,omitempty"`
    Virt       string `json:"virt,omitempty"`
    CPUModel   string `json:"cpu_model,omitempty"`
    CPUCores   int32  `json:"cpu_cores,omitempty"`
    CPUThreads int32  `json:"cpu_threads,omitempty"`
    MemTotal   int64  `json:"mem_total,omitempty"`
    SwapTotal  int64  `json:"swap_total,omitempty"`
    DiskTotal  int64  `json:"disk_total,omitempty"`
    BootAtMs   int64  `json:"boot_at_ms,omitempty"`
    FactsHash  string `json:"facts_hash"`
}

// ---- server.config（notification，运行中变更采集参数）----
// 全部可选：只下发变了的项

type ServerConfigParams struct {
    IntervalFastS     *int  `json:"interval_fast_s,omitempty"`
    IntervalSlowS     *int  `json:"interval_slow_s,omitempty"`
    FactsMaxIntervalS *int  `json:"facts_max_interval_s,omitempty"`
    CollectConns      *bool `json:"collect_conns,omitempty"`
    NeedFacts         *bool `json:"need_facts,omitempty"`
}

// ---- 错误码 ----

const (
    ErrCodeParse          = -32700
    ErrCodeInvalidRequest = -32600
    ErrCodeMethodNotFound = -32601
    ErrCodeInvalidParams  = -32602
    ErrCodeTokenInvalid   = -32000  // agent 收到后停止重连
    ErrCodeVersionMismatch = -32001
    ErrCodeCapDisabled    = -32002
    ErrCodeExecTimeout    = -32003
    ErrCodeRateLimited    = -32004
)

// 第二期方法名，本期只留常量占位，不定义 params 结构体
const (
    MethodAgentResult    = "agent.result"
    MethodAgentPingRes   = "agent.ping_result"
    MethodAgentSpeedRes  = "agent.speedtest_result"
    MethodServerExec     = "server.exec"
    MethodServerUpgrade  = "server.upgrade"
    MethodServerPingTask = "server.ping_task"
    MethodServerSpeedtest = "server.speedtest"
)
```

### 为什么指标字段全用指针

`*float64` + `omitempty` 是唯一能区分「CPU 真的是 0%」和「没采到」的做法。
用值类型 + `omitempty` 会把真实的 0 也省略掉，落库时写成 NULL，**数据永久失真且无法回溯修正**。
这条不许简化。

## 约束

- **agent 与 dashd 共用这一份，绝不各写一份**
- 可选字段用指针或 `omitempty`。**采集失败的项是「省略」不是「填 0」**——
  填 0 会让「CPU 真的是 0%」和「没采到」永远无法区分，这个错一旦上线就没法回溯修正
- `slow` 档字段整体可选：只在 slow 周期到期那一轮出现
- 这个包**不许 import 任何其他 internal 包**，保持零依赖
- 时间字段一律 `*_ms`，epoch 毫秒整数

## 验收

1. `04-protocol.md` 里每个示例 JSON 都有一条对应测试，能反序列化成功且字段值正确
2. 序列化往返测试：结构体 → JSON → 结构体，结果相等
3. 省略字段的用例：不带 `cpu_pct` 的报文反序列化后能区分「未上报」与「值为 0」
4. `go list -deps ./internal/protocol` 里没有其他 internal 包

## 边界

**只定义结构体和常量，不写任何收发逻辑、不写 WebSocket 代码。**

## 变更纪律

本任务合并后**这个包锁定**。后续任务要改协议 → 停下上报 → 由设计方改
`04-protocol.md` 并升 `ProtocolVersion` → 指定一人改。
