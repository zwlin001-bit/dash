## 约束

- **驱动用 `github.com/sijms/go-ora/v2`（纯 Go）**，不用 godror。
  godror 需要 Oracle Instant Client（C 依赖），会毁掉单二进制部署（P3、P5）
- ★ **ADB 已关闭 mTLS，直接用连接串（TLS-only）连接，不使用 wallet。**
  `db.Config.WalletPath` 保留为空字符串即可（字段留着，将来换库或换环境可能用到）。
  若连接被监听器拒绝（ORA-12506），说明 OCI 侧的 mTLS 还没关闭或 ACL 没放行，
  **停下上报，不要自行改用 wallet**
- **`CGO_ENABLED=0` 编译出来的二进制必须能连上库**，`ldd` 要显示 not a dynamic executable
- **方言差异只允许三处**，全部关在 `dialect` 包里：
  | | Oracle | MySQL |
  |---|---|---|
  | 占位符 | `:1 :2` | `? ?` |
  | 分页 | `OFFSET n ROWS FETCH NEXT m ROWS ONLY` | `LIMIT m OFFSET n` |
  | upsert / 批量 | `MERGE INTO … USING (… FROM dual)` / 数组绑定 | `ON DUPLICATE KEY UPDATE` / 多行 VALUES |
  出现第四处说明设计错了，**停下上报，不要自己扩**
- **业务代码一律写 `?` 占位符**，由 `Rebind` 改写。业务代码**不许 import `dialect` 包**
- 连接池默认：`MaxOpen=20` `MaxIdle=10` `ConnMaxLifetime=30min`（ADB 会主动断长连接）

## 接口签名（照这个写，不要自己发挥）

```go
package db

type Config struct {
    Driver          string        // "oracle" | "mysql"
    DSN             string
    User            string
    Password        string
    WalletPath      string        // Oracle mTLS 用；MySQL 忽略
    MaxOpenConns    int           // 默认 20
    MaxIdleConns    int           // 默认 10
    ConnMaxLifetime time.Duration // 默认 30m
}

type DB struct{ /* 内含 *sql.DB 与 dialect */ }

func Open(ctx context.Context, cfg Config) (*DB, error)
func (d *DB) Close() error
func (d *DB) Ping(ctx context.Context) error

// 业务代码一律写 ? 占位符，由内部 Rebind 改写
func (d *DB) Query(ctx context.Context, q string, args ...any) (*sql.Rows, error)
func (d *DB) QueryRow(ctx context.Context, q string, args ...any) *sql.Row
func (d *DB) Exec(ctx context.Context, q string, args ...any) (sql.Result, error)

// 分页：传基础 SQL（不带 LIMIT/FETCH），由这里补方言
func (d *DB) QueryPage(ctx context.Context, q string, limit, offset int, args ...any) (*sql.Rows, error)

// 事务：fn 返回错误或 panic 都自动 Rollback
func (d *DB) WithTx(ctx context.Context, fn func(*Tx) error) error

type Tx struct{ /* 同样有 Query / QueryRow / Exec / BatchInsert / Upsert */ }

// 批量插入。rows 每行长度必须等于 len(cols)
func (d *DB) BatchInsert(ctx context.Context, table string, cols []string, rows [][]any) error

// upsert：keyCols 是冲突判定列，updCols 是命中时要更新的列
func (d *DB) Upsert(ctx context.Context, table string, keyCols, updCols []string, row map[string]any) error
```

```go
package dialect

type Dialect interface {
    Name() string
    Rebind(q string) string                                  // ? → :1 :2（oracle）/ 原样（mysql）
    Paginate(q string, limit, offset int) (string, []any)     // 返回补好的 SQL 和追加的参数
    UpsertSQL(table string, keyCols, updCols []string) string
    BatchInsert(ctx context.Context, ex Execer, table string, cols []string, rows [][]any) error
}

type Execer interface {
    ExecContext(context.Context, string, ...any) (sql.Result, error)
}

func Get(driver string) (Dialect, error)
```

### 语义约定

| 约定 | 说明 |
|---|---|
| `ErrNotFound` | 包装 `sql.ErrNoRows`，业务用 `errors.Is(err, db.ErrNotFound)` 判断 |
| **不在这层做重试** | 重试策略由调用方决定（落库丢批 vs 查询直接失败，策略完全不同） |
| `BatchInsert` 分片 | 单批超过 **1000 行**要自动分片。Oracle 数组绑定和 MySQL 单语句都有上限 |
| `Rebind` 幂等性 | 对已经是 `:1` 形式的 SQL 不做二次改写（防止重复调用出错） |
| 空 `rows` | `BatchInsert` 收到 0 行直接返回 nil，不发语句 |
| `Open` 失败 | 返回可读错误，**错误信息里不许出现密码**（用 `internal/logx` 的 redact） |

## ★ 必须交付方言 lint

`scripts/lint-sql.sh` 扫描 `internal/`（排除 `internal/db/dialect`）与 `agent/` 下的 `.go`，
命中下列任一即报错退出非 0，并接进 `make lint`：

```
ROWNUM | SYSDATE | NVL\( | DECODE\( | FROM dual | MERGE INTO
ON DUPLICATE | \bLIMIT\b | FETCH NEXT | RETURNING | CONNECT BY
```

**这是「可移植 SQL」这条原则唯一的自动化保障。没有它，多人接力下这条原则三周内必然烂掉。**

### ❌ F2 必须修 —— `lint-sql.sh` 慢到不可用

**1767 行 Go 代码跑超过 115 秒超时。** 原因：外层 `while read line` 逐行循环，
**每一行 spawn 5 个 grep 子进程**。代码量增长后会线性恶化，
`make lint` 将无法在 CI 里使用。

**修法**：整体一次扫描，不要逐行。

```sh
FILES=$(find internal agent -name '*.go' -not -path 'internal/db/dialect/*')
grep -nE -i '(ROWNUM|SYSDATE|\bNVL\(|FROM[[:space:]]+dual|MERGE[[:space:]]+INTO|ON[[:space:]]+DUPLICATE|FETCH[[:space:]]+NEXT|CONNECT[[:space:]]+BY)' $FILES && FAIL=1
```
每条规则一次 `grep -nE`，全仓库应在 **1 秒内**跑完。

### ❌ F3 必须修 —— 两处误报已实测确认

| 规则 | 误报的合法 Go 代码 |
|---|---|
| `["`].*\blimit\b.*["`]`（大小写不敏感） | `errors.New("rate limit exceeded")` |
| `\bRETURNING\b`（大小写不敏感） | `msg := "returning to caller"` |

这两种写法在真实代码里一定会出现，一旦误报，人的第一反应是把这条 lint 关掉——
**那等于放弃 P2 唯一的自动化保障**。

**修法**：只对**明显是 SQL 的上下文**告警。建议：
- `LIMIT` / `RETURNING` 只匹配**大写形式**（SQL 关键字惯例大写），
  去掉这两条规则的 `-i`
- 或要求同一字符串里同时出现 `SELECT|INSERT|UPDATE|DELETE` 才判定

**复验要求**：上面两行合法代码必须 exit=0，
同时 `"... ORDER BY id LIMIT ? OFFSET ?"` 仍必须 exit=1。
