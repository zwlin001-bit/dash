## 已经出事了

线上 alus 的 `/etc/dash/config.toml`：

```toml
[db]
driver = "mysql"
user = "admin"
dsn = "root:****@tcp(127.0.0.1:33306)/dash_test?parseTime=true"
```

★ **生产 dashd 连的就是测试库** —— `127.0.0.1:33306/dash_test`，
正是全仓库所有 `*_test.go` 硬编码的那个：

```go
// internal/control/test_helper_test.go:17 等多处
dsn = "root:root@tcp(127.0.0.1:33306)/dash_test?parseTime=true"
```

已确认的后果：

1. **`internal/control/download_test.go:70` 会 upsert `site.domain = 'custom.domain.org'`**
   → 这就是装机命令域名变成 `custom.domain.org` 的原因
2. `cmd/dashd/auth_regression_test.go:196` 会 `DELETE FROM user_sessions`
   → 会把人踢下线
3. 在这台机器上跑过一次 `go test ./...`，生产数据就被测试改写一次

★ **另外 P2-12 的 `make test-db-up` 会试图在 33306 上起 docker 容器，
而这个端口已经被本机 mariadbd 占着** —— 两边会打架。

## 目标

**让「生产连测试库」这件事在启动时就被拦住，而不是靠人看配置。**

## 约束

### ❶ 启动自检

dashd `serve` 启动时检查 DSN，命中下列任一条就**拒绝启动**并打印清晰原因：

- 数据库名是 `dash_test`、`test`、或以 `_test` 结尾
- 端口是 **33306**（约定的测试端口）
- DSN 用户是 `root` —— ★ 生产不该用 root 连库

★ **要留一个明确的逃生门**：`server.allow_unsafe_db = true`（配置文件或
`DASH_ALLOW_UNSAFE_DB=1`），开了就只警告不拒绝。
默认关闭，`setup.sh` 生成的 config 里**不写这一项**（同 `dev_no_auth` 的处理）。

### ❷ 测试侧也加一道

测试连库前检查：★ **如果目标库里存在 `nodes` 且行数 > 0，或存在 agent token，
就判定为「这看起来是生产库」并直接 `t.Fatal`**，
而不是欢快地往里写测试数据。

信息要说清楚：「拒绝在疑似生产库上跑测试。测试库应当是空的。」

### ❸ 端口冲突

`scripts/test-db.sh` 起容器前检查 33306 是否已被占用：

- 被占用且不是自己的容器 → ★ **报错并提示换端口**
  （`DASH_TEST_DB_PORT=33307 make test-db-up`），不要硬起

### ❹ `setup.sh` 侧

- `install` 生成 config 时，★ **默认数据库名用 `dash` 不是 `dash_test`**，
  并且**不要把 root 写进 DSN**
- `status` 增加一行显示当前连的库名与端口；★ 命中不安全特征时标红

## ★ 迁移现网数据（写进交付说明，不要自动执行）

## ❺ 顺带：加一道外链守卫

用户明确要求：借鉴阿里那部分代码时**不能引入三方网站**，
避免被恶意外链窃取信息（规则已写进 `docs/agy/03-rules.md`）。

交付 `scripts/lint-external-urls.sh`，扫 `internal/` `cmd/` `agent/` `web/src/` `scripts/`：

- ★ **命中任何 `http(s)://` 字面量即失败**，除非在白名单里
- 白名单只有三类，写死在脚本里：
  - `*.aliyuncs.com`（云厂商官方 API 域名，且只允许出现在 provider 目录下）
  - `localhost` / `127.0.0.1`（本地默认值）
  - 文档与注释里的 GitHub 参考链接（`docs/` 不在扫描范围内）
- ★ **测试文件里的 `httptest` 地址是运行时生成的，不是字面量**，天然不受影响；
  如果测试里有硬编码外部地址，一律视为违规
- 挂进 `make lint`

★ **先在当前 main 上跑一次**，把已有的命中列出来 ——
如果有，逐个判断是该删还是该进白名单，**结论写进交付说明**。

3. DSN 用户是 `root` → 同样拒绝

8. `setup.sh status` 显示当前库名与端口
9. `make lint`、`make test` 全绿
