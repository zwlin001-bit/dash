## 接口签名（照这个写）

```go
package events

type Event struct {
    Type       string         // 如 "node.offline"
    Source     string         // 模块名，如 "control"
    TargetKind string         // "node" / "user" / ""
    TargetID   string
    Title      string
    Payload    map[string]any // 模板变量，见 09-events-notify.md §5.2
    DedupKey   string         // 如 "node.offline:<node_id>"，可空
    OccurredAt int64          // 0 表示用当前时间
}

// ★ Emit 永不返回错误、永不阻塞。写不进去只打日志。
// 事件系统故障绝不允许影响业务流程。
func Emit(ctx context.Context, e Event)

// 注册内置事件类型，进程启动时调用，写入 event_types 表（已存在则只补默认值不覆盖用户设置）
func RegisterType(t TypeDef)

type TypeDef struct {
    Type               string
    DisplayName        string
    DefaultSeverity    string // info / warning / critical
    DefaultDisposition string // drop / store / store+ui / store+notify
    Description        string
}
```

`Emit` 内部：查 `event_types` 的当前 `disposition`（内存缓存，类型策略变更时失效）→
`drop` 直接返回 → 其余写入 `events`。**写库走异步队列**，`Emit` 只做一次 channel 投递。

表结构见 [`../../10-schema-spec.md`](../../10-schema-spec.md) §4。
接口见 [`../../12-api-spec.md`](../../12-api-spec.md) §7。

## 约束

- ★ **`Emit()` 必须是非阻塞的、永不返回错误给调用方。**
  事件写不进去只能打日志，**绝不允许因为事件系统故障而让业务失败**
- ★ **`emit()` 是全工程唯一的事件入口。** 不允许模块自己往 `events` 表写
- `store+notify` 在第一期**只是入库时打个标记**，不做任何外发——渠道和路由是第二期
- **事件类型由代码定义，界面不能新增**，只能改级别和处置方式
- `payload_json` 里要放齐 `09-events-notify.md` §5.2 表里列的变量。
  **新增事件类型时同步补那张表**，否则第二期写模板的人不知道能用什么变量
- `dedup_key` 用于同类事件去重，形如 `node.offline:<node_id>`
- 事件保留 90 天，走任务 12 已有的分块清理机制，**不要另写一套清理**
- 表和列名照 `04` 的规范：小写、不加引号、≤30 字符、避开保留字、时间用 `*_ms`

## 验收

1. 六种事件都能在对应操作后正确产生，`events` 表里能查到
2. **停掉数据库，触发一次节点上线，业务正常完成，只在日志里看到事件写入失败**
   —— 这条是 `Emit()` 非阻塞的关键验证
3. 界面时间线能按类型、级别、目标节点过滤，未读数正确
4. 在界面上把 `node.online` 的处置改成 `drop`，之后该类事件不再入库
5. `09-events-notify.md` §5.2 的变量表已按实际 payload 补全
6. `scripts/lint-sql.sh` 通过；两份 DDL 对比测试通过
