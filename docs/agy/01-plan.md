## 3. 并行波次（按这个分派）

### Wave 0 — 独占，**不可并行**

| 任务 | 说明 |
|---|---|
| **T0.1** | 一个人做完再放其他人进来。它定义目录结构、`go.mod`、`Makefile`、**模块注册接口**，所有人都要在它上面加东西 |

同时进行（不占开发资源）：**T0.0a 由你在 OCI 控制台下载 wallet**。

> **重要之一**：T0.0 不阻塞代码开发。T0.2 / T0.3 可以先用本地 docker MySQL 8 开发验证，
> Oracle 侧的验证等 wallet 到位再补。**不要因为连不上 ADB 就停工。**
>
> **重要之二**：`T0.0b` 是**载荷性假设验证**，wallet 一到手就立刻做，优先级高于一切开发任务。
> go-ora 若不支持这个 wallet，数据库驱动选型要推翻重来，越晚发现代价越大。
> **它跑通之前，车道②不要投入超过 T0.2 的工作量。**

### Wave 1 — 4 条并行车道

| 车道 | 任务 | 备注 |
|---|---|---|
| ① | **T0.5** → **T1.3** | 同一人接着做：他定的协议，他写传输层最顺 |
| ② | **T0.2** → **T0.3** → **T0.4** | 串行，必须同一人。这条是关键路径，最长 |
| ③ | **T1.1** | 纯 `/proc` 解析，零外部依赖，完全独立 |
| ④ | **T5.0** | 前端脚手架，接 mock 数据，不依赖任何后端接口 |

**车道②是关键路径**，它一完成就解锁 6 个任务。优先给最快的人。

### Wave 2 — 最多 8 条并行车道

| 任务 | 解锁条件 |
|---|---|
| **T1.2** 主循环 | T1.1 + T1.3 完成 |
| **T2.1** 连接管理 | T0.5 + T0.3 |

这一波是并行度最高的时候。**T2.3 / T2.4 / T3.3 / T4.1 四个互不相干，可以随便派。**

## 4. 并行冲突规则（多个 AGY 同时干活必须遵守）

| 文件 / 目录 | 所有者 | 规则 |
|---|---|---|
| `internal/protocol/` | **T0.5 的负责人** | 其他任务**一律不改**。需要改协议 → 报给调度方 → 我出设计变更 → 指定一人改并升版本号 |
| `migrations/0001_init.*.sql` | **T0.3 的负责人** | 定稿后**任何人不许改**。需要新表/新列 → 新建下一个编号的迁移文件 |
| `migrations/NNNN_*` 编号 | 调度方分配 | 派发任务时一并告知该任务可用的编号，**避免两个人抢同一个编号** |
| `cmd/dashd/main.go` | T0.1 定型 | 后续任务**只允许加一行模块注册**，不改装配逻辑 |
| `Makefile` | T0.1 定型 | 只允许追加 target |
| `go.mod` / `go.sum` | 共有 | 冲突时直接 `go mod tidy` 重生成，不手工合并 |
| `docs/` | 各任务 | 只改自己任务相关的段落。改 `PRINCIPLES.md` 一律不允许 |
| 其余 | 任务独占 | 每个任务的交付物目录见任务文件的「交付物」段 |

**分支约定**：一个任务一个分支，`agy/T2.3-rollup` 这样命名，完成后 PR 回 `main`。
**不要多个任务共用一个分支**——那等于放弃了并行的意义。

## 6. 关键路径与预估

关键路径是：`T0.1 → T0.2 → T0.3 → T2.1 → T2.2 → T4.3 → T5.1b`

想压缩总时长，优先保证 **T0.1 和车道②（T0.2→T0.3→T0.4）** 不卡壳。
其他车道即使慢一点也不影响总工期。

**T0.1 做完之前不要派第二个人。** 骨架没定型时多人并行只会互相冲突。

**T0.0b 没跑通之前，不要让车道②越过 T0.2。** 驱动选型没坐实就写 T0.3 的两份 DDL，
一旦要换驱动/换连接方式，返工量最大的就是它。
